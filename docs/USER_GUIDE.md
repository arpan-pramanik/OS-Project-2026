# User Guide: Building, Loading, and Testing the Task Lister Module

This practical guide provides step-by-step instructions for compiling, loading, querying, and verifying the `task_lister` Linux kernel module.

---

## 1. Prerequisites & Kernel Headers

To build Linux kernel modules, the kernel development headers matching your running kernel version must be installed.

### Verify Running Kernel:
```bash
uname -r
```

### Installation by Distribution:

#### Arch Linux:
```bash
sudo pacman -S linux-headers base-devel
```

#### Ubuntu / Debian / Linux Mint:
```bash
sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)
```

#### Fedora / RHEL / CentOS:
```bash
sudo dnf install gcc make kernel-devel-$(uname -r)
```

---

## 2. Compilation

To compile both the kernel module (`task_lister.ko`) and the user-space companion utility (`tools/reader`):

```bash
make
```

### Build Output:
- `task_lister.ko`: The compiled kernel module binary.
- `tools/reader`: The compiled user-space CLI reader tool.

### Inspect Module Metadata:
```bash
make info
# Or directly:
modinfo task_lister.ko
```

### Clean Build Artifacts:
```bash
make clean
```

---

## 3. Loading the Module

Loading a kernel module into supervisor space requires administrative privileges (`sudo`).

### Quick Load via Helper Script:
```bash
./scripts/load.sh
```

### Manual Load via `insmod`:
```bash
# Load with default mode (prints both linear list and tree to dmesg)
sudo insmod task_lister.ko

# Load with linear-only mode
sudo insmod task_lister.ko mode=linear

# Load with tree-only mode
sudo insmod task_lister.ko mode=tree
```

---

## 4. Viewing Output

Once loaded, output is accessible through two distinct channels:

### 4.1 Viewing Kernel Ring Buffer Logs (`dmesg`)
```bash
# View last 50 entries generated by task_lister
make dmesg

# Or manually:
dmesg | grep "\[task_lister\]" | tail -n 50
```

## 5. Using the User-Space Companion Reader

The `tools/reader` binary provides client-side filtering, searching, and analytics on top of the `/proc/task_lister` stream:

```bash
# View all tasks formatted
./tools/reader --all

# View the hierarchical process tree
./tools/reader --tree

# Filter by Process ID
./tools/reader --pid 1

# Filter by Command Name (case-insensitive substring)
./tools/reader --comm bash

# Filter by Task State (e.g. Running tasks only)
./tools/reader --state R

# Show only user-space processes
./tools/reader --user

# Show only kernel threads
./tools/reader --kernel

# Show only aggregate system statistics
./tools/reader --stats
```

## 6. Running Automated Verification

To verify that the kernel module is functioning accurately and that its task count matches user space `ps`:

```bash
make test
# Or:
./scripts/verify.sh
```

---

## 7. Unloading the Module

To safely unload the module and remove all procfs pseudo-files:

```bash
# Via helper script:
./scripts/unload.sh

# Or directly:
sudo rmmod task_lister
```

Verify clean removal:
```bash
dmesg | grep "\[task_lister\]" | tail -n 5
```

## 8. Troubleshooting

### Issue 1: `make: *** /lib/modules/.../build: No such file or directory`
- **Cause**: Kernel development headers for the running kernel are missing.
- **Fix**: Install the `linux-headers` package matching your `uname -r` as detailed in Section 1.

### Issue 2: `insmod: ERROR: could not insert module task_lister.ko: Operation not permitted`
- **Cause**: Attempting to load a kernel module without root privileges.
- **Fix**: Run `sudo insmod task_lister.ko` or `./scripts/load.sh`.

### Issue 3: `insmod: ERROR: could not insert module: Key was rejected by service`
- **Cause**: UEFI Secure Boot is active and requires all kernel modules to be digitally signed with a Machine Owner Key (MOK).
- **Fix**: Temporarily disable Secure Boot in UEFI/BIOS settings or enroll a custom MOK key to sign `task_lister.ko`.

### Issue 4: `rmmod: ERROR: Module task_lister is in use`
- **Cause**: A user space process currently has `/proc/task_lister` or `/proc/task_lister_tree` open (e.g., a hung `cat` or editor).
- **Fix**: Identify and close the process using `lsof /proc/task_lister` before running `rmmod`.
